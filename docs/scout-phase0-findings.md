## Risks / surprises

- There is no Scout detail page. The only page that opens one person is the People page, `PersonPage.tsx`. The feature prompt also says not to touch Recruitment pages. Do not edit that page until you say it is the page you mean.
- A scout has one sector, not several. The distance function can still accept a list. Today that list has one item from `scout_applications`.
- Assign needs the scout’s user id (`users.id` of an approved vet). A recruitment contact id is not that id. If the person has no approved scout account, assign returns “That scout is not ready.”
- The same sector name can exist in two districts (the map test checks Busasamana in Nyanza and in Rubavu). The center key must be district plus sector.
- `pipeline_lots.contact_phone` exists. This feature must not select it.
- `ready_from` is required in the database. “No ready date” is unlikely. The sorter should still put a missing date last, because the weigh queue already uses `NULLS LAST`.
- The weigh queue’s “within 7 days” line is only for a scout looking at their own list. It is not the definition of “still needs a visit.”
- Sector centers live in the web app. The server already reads location JSON with `readFileSync` for districts. A later phase can follow that pattern. No new library and no database column are required for that.
- Do not change Insights, Recruitment analytics, or CRM. `recruitmentContacts.js` already builds a one-sentence area count. That is a different feature and should stay as it is.

## NOT FOUND items and what you propose

- **Scout detail page.** Stop and confirm the page before any UI work. Proposal: add the section on `web/src/pages/market/PersonPage.tsx` only when `want` is `scout` and the person has a `userId`, and only for desk staff (`canAccessPipelineDesk`). Leave Insights and Recruitment analytics files unchanged.
- **Several sectors per scout.** Use the single `scout_applications.district` and `scout_applications.sector`. Pass them as a one-item list. No migration.
- **Neighbor / adjacency data.** Use the 10 km rule between sector centers. No migration.
- **Short flock reference on the weigh queue.** The weigh queue does not show a public code. The flock book shows `farmLabel` or the word “Flock”. Proposal: use that same label, and keep the lot id only as the value sent to the existing assign call.
